# 历史甘特图版本回看设计

## 目标

在生产指挥总览的现有甘特图内增加历史版本回看能力。用户无需离开总览页，即可选择某次正式发布的排程快照，并继续使用设备视角、订单视角和工序筛选查看当时的排程。

## 范围

仅在以下正式状态变更后生成快照：

1. 首次正式排产；
2. 人工调序确认；
3. 紧急插单正式发布；
4. 设备故障或其他事件重排正式发布。

页面筛选、视角切换、横向滚动和候选方案预览不生成历史版本。完工登记是否触发重排，按其是否发布新的正式排程决定，而不是按按钮点击本身决定。

## 界面设计

在“设备甘特图 / 订单甘特图”卡片标题栏右侧、现有视角按钮之前增加版本选择器：

`[当前计划 ▼] [设备视角] [订单视角] [全部工序] [拉丝] [捻股] [合绳] [仅看风险]`

版本条目显示“发布时间｜发布原因”。选择历史版本后：

- 卡片标题改为“历史甘特图”；
- 显示“历史版本·只读”、版本时间、操作人和发布原因；
- 保留设备视角、订单视角、工序筛选和风险筛选；
- 提供“返回当前计划”；
- 不提供拖动、发布、覆盖或修改历史版本的操作。

无历史记录时，选择器只显示“当前计划”，不展示空菜单或空白图表。

## 后端架构

新增独立的排程历史存储模块，负责：

- 从当前正式 dashboard 创建不可变快照；
- 为快照生成稳定版本号；
- 原子写入本地 JSON 存储；
- 返回倒序版本摘要列表；
- 按版本号读取完整快照；
- 最多保留最近 100 个正式版本。

每个快照至少包含：

- `schedule_version`：版本号；
- `created_at`：发布时间；
- `created_by`：操作人；
- `reason`：发布原因；
- `event_type`：首次排产、人工调序、紧急插单或事件重排；
- `parent_version`：上一个正式版本；
- `dashboard`：用于恢复当时甘特图、订单、风险和 KPI 的完整只读数据。

历史文件位于后端可写数据目录，不保存在浏览器 localStorage。服务重启后仍可读取。

## 接口

### `GET /api/schedule/history`

返回历史版本摘要，按发布时间倒序排列，不返回大体积甘特数据。

### `GET /api/schedule/history/{schedule_version}`

返回指定版本元数据和完整 dashboard 快照。版本不存在时返回 404。

现有 `/api/dashboard` 继续只返回当前正式计划，避免历史选择污染实时数据源。

## 数据流

正式排程发布成功后，后端先完成正式状态更新，再以该正式状态创建快照。快照失败时保留已发布计划，同时写入明确错误日志并向发布接口返回“计划已发布、历史留档失败”的警告，不伪造成功留档。

前端初始化时并行读取当前 dashboard 与历史摘要。用户选择历史版本时仅请求该版本详情并替换甘特图的数据源；选择“当前计划”时恢复内存中的最新 dashboard。历史查看不会修改后端当前状态。

## 错误处理

- 历史列表不可用：继续展示当前计划，并提示“历史版本暂不可用”；
- 指定版本不存在或已清理：保持当前图表不变，并提示重新选择；
- 快照文件损坏：跳过损坏条目、记录日志，不影响当前排程服务；
- 请求过程中重复切换：仅最后一次选择生效，避免旧响应覆盖新选择。

## 测试与验收

后端测试覆盖快照创建、父版本关联、最多 100 版、原子持久化、重启恢复、列表接口、详情接口和 404。

前端测试覆盖选择器位置、当前/历史切换、只读标识、筛选复用、无历史空态、接口失败回退和重复请求竞态。

验收标准：正式发布一次重排后，刷新浏览器和重启后端仍能从标题栏选择该历史版本；历史甘特内容与发布时一致；返回当前计划后恢复最新数据；现有设备视角、订单视角、工序筛选和 PNG 导出不回归。
