# 七天滚动计划与历史定位设计

## 目标

正式排产以连续七天为一个周计划，同时避免历史周计划长期累计后难以定位。首页甘特图使用“月份 → 周计划 → 周内版本”三级定位，不把所有历史版本平铺在一个下拉框中。

## 七天计划口径

- 每个正式周计划覆盖连续七个自然日，首期从既定排产起点 2026-08-03 00:00 开始。
- 周期依次为 08-03～08-09、08-10～08-16，不重叠、不留空。
- 甘特图只精排当前七天；未在本周完成的任务保留已完成工序和剩余数量，自动结转下一周。
- 订单交期仍使用订单自身预计到货/预发货日期，不因周计划边界改变。
- 第 8～28 天作为粗排预测，只显示预计周次、瓶颈工序和风险，不展开成正式设备甘特任务。
- 28 天以后只保留在订单池并参与交期预警。

## 历史定位

甘特图标题栏使用三个紧凑选择器：

`[2026年09月] [09月21日—09月27日] [正式周计划]`

第一级按计划周的开始日期归属月份；第二级列出该月涉及的周计划；第三级列出该周内版本：正式周计划、紧急插单、人工调序、设备故障重排。

默认行为：

- 打开页面时选择当前计划，不进入历史只读状态；
- 打开历史选择器时默认当前月和最近一个有记录的周；
- 月份列表优先展示最近 12 个月，更早年份按年份折叠在完整历史中；
- 周计划提供“上一周 / 下一周”按钮；
- 周内版本按发布时间倒序，正式周计划固定显示在首位；
- 无记录的月份和周不生成空选项。

## 版本归属

历史快照增加：

- `week_start`：周计划开始时间；
- `week_end`：周计划结束时间；
- `plan_key`：如 `2026-W08-03` 的稳定周计划键；
- `version_type`：`weekly_official / rush_order / manual_adjust / event_replan`；
- `revision_no`：该周内递增版本号。

紧急插单和人工调整归入其生效任务所在的周计划，不另生成新的周。跨周影响仍记录在该版本的影响订单信息中。

## 接口与加载

历史摘要接口支持 `month=YYYY-MM`，只返回该月涉及的周计划和版本摘要；详情接口保持按版本号读取。前端首次只取最近月份摘要，切换月份时按需加载，避免多年数据一次性传输。

## 错误与边界

- 跨月周计划按 `week_start` 归属月份，界面日期范围仍显示完整七天；
- 周内正式版本缺失时允许显示事件版本，但标注“基线记录缺失”；
- 切换月份、周或版本失败时保持当前甘特图不变；
- 正在查看历史版本时，后台实时刷新不得覆盖历史图；
- 旧快照缺少周字段时，按快照创建时间推导归属，并标记为迁移数据。

## 验收

历史记录累计到多个自然月后，用户最多通过三次选择定位到任一周内版本；首页不出现超过一个月的平铺版本列表；上一周和下一周可以连续浏览；设备视角、订单视角、工序筛选、风险筛选和返回当前计划继续有效。
