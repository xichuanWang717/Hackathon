# 动态松弛时间排序 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用动态剩余松弛时间替换普通订单仅按交期的初始排序，并完成全量对比试算。

**Architecture:** 在独立的排序模块中计算现有产能参数下的最短完整工艺链时间和松弛时间，排产引擎只消费排序键。保持硬约束、批次放置和KPI计算不变。

**Tech Stack:** Python、pytest、现有启发式排产引擎。

**Spec:** `docs/superpowers/specs/2026-09-19-动态松弛时间排序-design.md`

## Global Constraints

- P0和人工规则高于算法偏好。
- 延期容忍不改变严格准时指标。
- 不修改现有工艺与设备硬约束。
- 不使用固定14天或365天主排产截止。

## Review Focus

- 同交期不同加工时间是否让长加工订单优先。
- 企业确认的72小时容忍是否只影响承诺松弛度。
- P0是否始终优先。
- 无匹配产能时是否安全回退而不报错。
- 全量排产是否仍通过硬约束校验。
