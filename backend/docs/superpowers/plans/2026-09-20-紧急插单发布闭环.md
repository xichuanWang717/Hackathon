# 紧急插单发布闭环 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 人工确认急单候选后，将急单正式加入订单中心并以同一排程版本更新甘特图、风险和 KPI。

**Architecture:** `/api/replan` 产生并暂存候选版本；`/api/replan/apply` 在后端原子发布。前端只消费后端候选与发布结果，不再通过 DOM 提示模拟成功。

**Tech Stack:** FastAPI、Pydantic、Python、原生 JavaScript、pytest。

**Spec:** `docs/superpowers/specs/2026-09-20-紧急插单发布闭环-design.md`

## Global Constraints

- 人工确认前不得修改正式排程。
- 发布必须校验急单完整排入与硬约束通过。
- 订单中心、甘特图、风险预警和 KPI 必须来自同一后端 dashboard。
- 操作者、原因、确认时间和前后 KPI 必须留痕。

## Review Focus

- 重复确认不能重复添加急单。
- 基线变化后的旧候选不能覆盖新排程。
- 不可应用方案必须返回明确错误而非成功提示。
- 新订单必须同时出现在 `engine.orders` 与正式 `base`。
- 页面刷新必须从 `/api/dashboard` 恢复发布结果。
