# 订单日期可见性 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让所有当前与历史排产只看见截至排产时点已经到达“订单日期”的订单，彻底阻断未来订单泄漏。

**Architecture:** 数据加载器负责把 Excel“订单日期”解析为 `Order.release_at`；正式排程入口以明确的 `as_of` 过滤未来订单；服务端为每个历史自然周使用该周一作为 `as_of` 独立构建并覆盖系统回放快照。前端只展示快照携带的数据截止时间，不自行推断订单可见性。

**Tech Stack:** Python 3、pandas、FastAPI、pytest、原生 JavaScript。

**Spec:** `docs/superpowers/specs/2026-09-22-订单日期可见性-design.md`

## Global Constraints

- 所有订单仅按 Excel“订单日期”生效，单据日期不参与算法。
- `release_at > as_of` 的订单不得进入订单、KPI、风险或甘特图结果。
- 订单日期缺失或无效时必须成为数据异常，禁止以单据日期兜底。
- 历史周的 `as_of` 固定为周一 00:00；当前计划使用平台北京时间。
- 真实发布快照不可覆盖；只有 `REPLAY-YYYYMMDD` 系统回放可重建。

## Review Focus

- 订单日期恰好等于周一 00:00：应在本周可见。
- 单据日期更早、订单日期更晚：订单日期未到前仍不可见。
- 订单日期缺失：订单进入数据异常，不进入排程。
- 跨月自然周 08-31—09-06：仍以 08-31 00:00 为截止时点。
- 重启重复回放：稳定覆盖同一系统回放，不产生重复版本。
