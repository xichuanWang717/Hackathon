# 排产解释与上传状态 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复排产进度停在 5% 和切页丢失，并在现有右侧栏展示真实排程解释。

**Architecture:** 后端排产构建函数通过回调发布阶段进度，presenter 为甘特任务和订单输出解释索引；前端桥接层持久化数据版本与任务状态，app.js 根据选择对象渲染解释。

**Tech Stack:** FastAPI、Python、原生 JavaScript、CSS、pytest、Playwright CLI

**Spec:** `docs/superpowers/specs/2026-09-19-排产解释与上传状态设计.md`

## Global Constraints

- 保留现有三栏布局和视觉系统。
- 解释只来自真实后端数据。
- 上传状态跨页面恢复，后端状态优先。
- 已完成订单继续从排产集合筛除。

## Review Focus

- 页面切换后上传校验摘要、确认状态和进度应恢复。
- 运行过程中进度应出现 5% 与 100% 之间的阶段值。
- 无 trace 的任务应显示空状态而不是虚构规则。
- 换型任务应显示 R3 依据和耗时。
- 多次点击开始排产不得重复提交。
