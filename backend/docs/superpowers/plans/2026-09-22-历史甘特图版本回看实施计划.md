# 历史甘特图版本回看实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在生产指挥总览的现有甘特图内增加可持久化、只读的正式排程历史版本回看功能。

**Architecture:** 后端用独立 `schedule_history.py` 管理不可变 JSON 快照及最近 100 版保留策略，`server.py` 暴露版本列表和详情接口，并在正式发布点写入快照。前端桥接层封装历史请求，`app.js` 只切换甘特数据源，不改变当前正式 dashboard。

**Tech Stack:** Python 3.13、FastAPI、pytest、原生 JavaScript、HTML、CSS。

**Spec:** `docs/superpowers/specs/2026-09-22-历史甘特图版本回看-design.md`

## Global Constraints

- 仅首次正式排产、人工调序确认、紧急插单正式发布和事件重排正式发布生成快照。
- 历史版本只读，不得修改或覆盖当前正式排程。
- 快照必须在服务重启后仍可读取，最多保留最近 100 个正式版本。
- 当前 `/api/dashboard` 行为不变。
- 历史接口失败时，当前甘特图必须继续可用。
- 沿用现有深色工业指挥台视觉系统，不新建独立历史页面。

## Review Focus

- 历史文件为空或不存在时，应返回空列表而不是 500；由 Task 1 测试覆盖。
- 单个快照文件损坏时，应跳过损坏项且不影响其他版本；由 Task 1 测试覆盖。
- 同一正式版本重复留档时，不得产生重复记录；由 Task 1 测试覆盖。
- 用户快速连续选择版本时，旧请求不得覆盖最后一次选择；由 Task 3 测试覆盖。
- 历史接口失败或版本已清理时，应保持当前甘特不变并显示提示；由 Task 3 测试覆盖。
